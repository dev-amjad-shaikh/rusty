# The demand-side learning loop: the gap ledger

*Status: wave 1 (core contracts + ledger store), wave 2 (server persistence + `/gaps` surface + runtime filing), wave 3 (induction, core + `/induction/run` server surface), wave 4 (the hunting loop: `/hunts` + promotion-gated closure), and wave 5 (outcome annotations: majority-voted scoring, automatic failure-rate closure, per-intent curves) landed. Frontier expansion turns on after hunting is proven in production.*

---

## 1. The gap this plane fills

Every supply-side half of self-knowledge already exists in this runtime: `learn.rs` is the governed candidate pipeline (what was learned, evaluated, promoted, rolled back), `memory.rs` carries provenance columns, `skill_distill.rs` drafts skills from trajectories, `self_improve.rs` keeps the capability backlog. All of it is reactive — each mechanism learns from traffic that has already happened, so every lesson is paid for by at least one degraded interaction.

The demand side is the missing organ: a first-class, permanently maintained record of what the agent does **not** yet know, derived from demand evidence (searches, tickets, escalations, corrections, zero-recall lookups) rather than from supply introspection. No studied platform in the best-of-breed corpus has it; the research library's cold-start document (`reference/learning-loops-and-cold-start.md`) designs it, and this plane implements that design.

The one-sentence thesis the build order encodes: **teach the system to represent its ignorance first, make learning governed second, make it measured third.**

## 2. What wave 1 ships

`rusty-core/src/gaps.rs` — pure contracts and the in-memory ledger store. No IO, no clocks, no journal event kinds; timestamps are injected and the whole ledger serializes as one versioned snapshot (`LEDGER_FORMAT_VERSION = 1`, fail-closed on anything else).

**The interaction event.** The uniform record every demand signal normalizes into: source (system / stream / record id — the citation anchor), role-typed pseudonymizable actor, channel (`portal_search` / `chat` / `request` / `incident` / `case` / `escalation`), utterance, resolution path, outcome, timestamps, and links to related events. The corpus's one non-negotiable ingestion rule — *preserve the failures* — is structural: `no_result`, `no_click`, `reopened`, `escalated`, `abandoned`, `unresolved` are first-class variants. Event ids are content addresses (`ie-<sha256>`), so a re-run connector converges instead of double-counting, and a colliding id with different content is a typed error. Intent assignment is the only mutable fact about an event, and it mutates through versioned `IntentAssignment` records, never in place.

**The gap-ledger entry.** One thing the agent does not know: subject (mined `intent` or free `question_shape`, normalized for matching), statement, a **non-empty evidence list** (an entry without citations is invalid by schema — ignorance is held to the same evidentiary standard as knowledge), origin class, volume × failure-cost priority, typed closure criteria, and a validated status machine (`open → hunting → trial_pending → closed`, `blocked_on_business`, `parked`, `reopened`). Origin classes are load-bearing because the ledger will drive autonomous background work: `induction`, `runtime_escalation`, `runtime_correction`, `zero_recall`, `operator`, `untrusted_derived`, and `speculative{structural|statistical|model_prior}` — the last subtyped by the adjacency that justified the widening, which is what keeps frontier expansion explicable.

**The mutation log.** Entries are projections; the store of record is a per-gap hash chain of content-addressed mutations (`gm-<sha256>` over the previous head, so the chain is tamper-evident). `Filed` carries the full filing payload, so a chain rebuilds its entry with no state beside the log. Rollback appends a `RolledBack` link and re-folds from the target prefix — the restore is the state that was, byte-exact, never a reconstruction. This is the same discipline `learn.rs` applies to candidates, applied to ignorance.

**Runtime filing.** `file_escalation`, `file_correction`, `file_zero_recall` turn the three highest-value runtime signals into ledger rows. Dedupe is reinforcement, not duplication: a second filing against an open gap adds volume, failure-cost, and evidence to the existing entry; a filing against a **closed** gap reopens it — the ledger never forgets a gap closed on paper but not in practice.

**The frontier.** `open_speculative` files gaps discovered by widening along structural / statistical / model-prior adjacencies. Speculation cannot cite itself as evidence: an unvalidated speculative entry cannot transition to `hunting` and never appears in `work_order()`. A demand probe (`record_probe`) validates — the entry becomes observed, gains the probe as citation, and enters the ordinary priority queue — or parks the entry under a decay clock (`base * 2^(n-1)` grace after the n-th empty probe, expiry after `MAX_EMPTY_PROBES` with resolution `expired:no-demand`).

**The behavioral signal.** `record_outcome` tallies accepted / corrected / redone per intent — a redo or correction is negative signal even when it reads as a polite new instruction (the process-reward insight). Closure is mechanical: `evaluate_closure` checks typed criteria (`artifact_promoted`, `block_filled`, `failure_rate_below`, `business_decision_required`) against evidence and closes with a resolution link, or refuses with a typed error. `sweep_reopens` reopens closed entries whose measured failure rate says the closure did not hold — the self-honesty pass.

## 3. Composition with the existing planes

The ledger deliberately rides existing contracts rather than inventing parallels:

- **Closure by promotion** names `learn.rs` candidate ids — a gap closes when its candidate passes the same promotion gate everything else passes. Nothing a hunt produces is auto-promoted; the ledger queues behind the gate with better evidence.
- **The behavioral signal** consumes per-intent outcomes; the turn-provenance stamp (session identity, main/side classification, turn boundaries on every provider call) is the natural producer and remains a separate, small stream.
- **Snapshots** are plain serde values; a server wave persists them through the established store backends without a translation layer.
- **Goldens** pin every wire shape under `rusty-core/tests/golden/gaps_*.json`, so contract drift fails CI the way every other plane's does.

## 4. Wave plan

- **W1 (this wave, landed):** core contracts, the ledger store, the status machine, probes and the frontier, closure + behavioral signal, rollback, snapshot roundtrip. 36 tests, 5 goldens.
- **W2 (landed):** server persistence (both store backends — the JSON backend keeps one snapshot file per tenant under `gaps/`, the Postgres backend a `gap_ledgers` table), the `/gaps` route surface (event ingest, filing, the runtime-shaped filing endpoints, speculative entries, probes, transitions, closure, rollback, outcomes, the sweep, the work order), and the two runtime filing hooks: a named-question memory miss files a zero-recall gap, and a stored operator correction files a runtime-correction gap citing the derived record. Both hooks are best-effort — the read (or write) is already served, so a filing failure is logged, never surfaced. 16 integration tests.
- **W3 (landed, core):** induction — `induction.rs` mines the event corpus into the ranked, evidence-cited intent map (FTS+taxonomy clustering, deterministic and byte-reproducible; reassignment diffs for later passes), inverts reachable supply into confidence- and freshness-graded coverage claims, joins the two maps into the gap matrix (working / failing supply, learn-now, latent), seeds the ledger from the learn-now and failing cells with `origin: Induction`, and emits the declared-block schema for the top intents. 17 tests, 3 goldens.
- **W3b (landed, server):** `POST /induction/run` — one composite pass over the tenant's ledger: mine the event corpus, re-place events through appended versioned reassignments (never in place), invert the supplied artifacts into coverage, join the matrix, optionally seed the ledger, and answer with every map (projections: answered, never stored). 5 integration tests. The crawl's execution (read-only connectors under the guard pipeline, `side`-stamped research sessions) remains a follow-on.
- **W4 (landed):** the hunting loop — `POST /hunts/cycle` spends a bounded budget (default 1, cap 64) moving the work order's top entries to `hunting`; `POST /hunts/{gap_id}/draft` attaches an existing learning candidate and moves the gap to `trial_pending`; `POST /hunts/{gap_id}/blocked` cites the contradiction on the entry (a zero-volume reinforcement via the new `add_evidence`) and parks it `blocked_on_business`. Closure is not a hunt verb: the promotion gate's `close_gaps_on_promotion` sweep (best-effort, after the promotion commits) closes every gap whose criteria name the promoted candidate. Core gained `entries()` for the sweep. 3 core tests, 6 integration tests. Frontier expansion turns on after hunting is proven.
- **W5 (landed):** the behavioral signal with its evidence attached — `OutcomeAnnotation` scores a served turn by majority vote across recorded `JudgeVote` samples (a tie abstains to the new `Neutral` class, which stays out of the failure-rate denominator), content-addressed so re-scoring converges by identity and collisions fail typed. `record_annotation` evaluates failure-rate closure for the intent's un-closed entries in the same mutation — a criterion the fresh numbers satisfy closes with no human bookkeeping. The curve is queryable per intent (`outcome_curve`), and the whole annotation log rides the snapshot (additive, defaults to empty — pre-annotation snapshots still load). Server: `POST /gaps/annotations` (201/200 by identity) and `GET /gaps/intents/{intent_id}/outcomes`. 9 core tests (1 golden), 3 integration tests. Still open for EP-07-S12: the provider-seam turn-stamp invariant (AC 1), the judge integration itself (the vote machinery is here; the sampler is not), and the retention-score penalty coupling (AC 5).

Open questions for W2+: whether gap mutations should also journal as `RunEventKind` variants (deferred deliberately — the ledger is per-deployment state, not per-run evidence); the failure-cost weighting vocabulary (carried opaquely as milli-units for now); and whether intent clustering lives in the runtime or in `rusty-eval`-adjacent tooling.
